## Этап 2. Страницы и матрица требований

### 2.1. Список страниц и маршрутов

| Маршрут / экран                        | Назначение                         | Как пользователь попадает | Основное действие                          |
| -------------------------------------- | ---------------------------------- | ------------------------- | ------------------------------------------ |
| `/events` — Каталог                    | Поиск и выбор учебного мероприятия | Из основной навигации     | Найти, отфильтровать и открыть мероприятие |
| `/events/:slug` — Мероприятие          | Просмотр подробной информации      | Из карточки каталога      | Изучить описание и перейти к записи        |
| `/events/:slug/register` — Регистрация | Отправка заявки на участие         | По кнопке «Записаться»    | Заполнить и отправить форму                |

Основной пользовательский поток: **каталог → карточка мероприятия → регистрация → подтверждение**.

### 2.2. Матрица требований по экранам

| Требование                 |      Каталог      | Мероприятие | Регистрация | Комментарий                                      |
| -------------------------- | :---------------: | :---------: | :---------: | ------------------------------------------------ |
| Название и категория       |         ✓         |      ✓      |      ✓      | Нужны для ориентации в контексте события         |
| Дата и время               |         ✓         |      ✓      |      ✓      | В форме показываются в кратком резюме            |
| Место проведения           | В карточке кратко |      ✓      |  В резюме   | Может быть офлайн или онлайн                     |
| Поиск, сортировка, фильтры |         ✓         |      —      |      —      | При изменении обновляется набор результатов      |
| Пагинация                  |         ✓         |      —      |      —      | Сбрасывается на первую страницу после фильтрации |
| Избранное                  |         ✓         |      ✓      |      —      | Состояния off/on должны синхронизироваться       |
| Вкладки                    |         —         |      ✓      |      —      | «Описание», «Программа», «Спикеры»               |
| Запись на мероприятие      |      Переход      |      ✓      |      ✓      | Недоступна при отсутствии мест                   |
| Валидация формы            |         —         |      —      |      ✓      | Ошибка связана с конкретным полем                |
| Loading / empty / success  |         ✓         |      ✓      |      ✓      | Нужны даже при отсутствии на основном макете     |

### 2.3. Данные и ограничения контента

| Элемент          | Данные                                             | Риск                        | Требование к интерфейсу                              |
| ---------------- | -------------------------------------------------- | --------------------------- | ---------------------------------------------------- |
| Карточка события | Название, категория, дата, место, места            | Длинное название, нет мест  | Ограничить переносы; явно показать отсутствие мест   |
| Фильтры          | Категория, дата, формат, доступность               | Много выбранных значений    | Показывать активные фильтры и действие «Сбросить»    |
| Страница события | Описание, программа, спикеры, организатор          | Разная длина вкладок        | Сохранять устойчивую структуру без скачков навигации |
| Форма            | ФИО, e-mail, группа, формат, комментарий, согласие | Ошибки и повторная отправка | Локальные подсказки; блокировка на время отправки    |

Проверка полноты: учтены все три экрана, повторяемые сущности, ошибки формы и состояния
loading, empty и disabled.

## Этап 3. Декомпозиция на компоненты

### 3.1. Кандидаты в повторно используемые компоненты

| Компонент          | Где используется     | Ответственность                       | Основные данные / состояния            | Почему отдельный                                 |
| ------------------ | -------------------- | ------------------------------------- | -------------------------------------- | ------------------------------------------------ |
| `AppHeader`        | Все экраны           | Навигация и текущий раздел            | active link, mobile menu               | Повторяется на каждой странице                   |
| `EventCard`        | Каталог              | Краткое представление события         | title, category, date, seats           | Многократно повторяется в сетке                  |
| `FavoriteButton`   | Каталог, мероприятие | Добавление в избранное                | off/on, aria-pressed                   | Имеет собственное состояние в двух контекстах    |
| `FilterPanel`      | Каталог              | Управление расширенными фильтрами     | selected, reset, expanded              | Самостоятельная логика и мобильное представление |
| `StatusMessage`    | Все экраны           | Сообщения loading/error/empty/success | type, title, text                      | Единый паттерн обратной связи                    |
| `Tabs`             | Мероприятие          | Переключение разделов контента        | active, hover, focus                   | Управляет связанными панелями и клавиатурой      |
| `RegistrationForm` | Регистрация          | Сбор, валидация и отправка данных     | empty, filled, error, loading, success | Самостоятельный жизненный цикл формы             |

Наиболее важны `EventCard`, `FavoriteButton` и `StatusMessage`: первый формирует повторяемую
единицу каталога, второй синхронизирует общее состояние, третий унифицирует системную обратную
связь.

### 3.2. Что не выделяется в отдельный компонент

| Фрагмент                    | Где находится                 | Почему остаётся внутри родителя                               |
| --------------------------- | ----------------------------- | ------------------------------------------------------------- |
| Заголовок страницы          | На каждом экране              | Простая разметка без собственной логики                       |
| Краткое резюме события      | Форма регистрации             | Используется один раз и тесно связано с формой                |
| Отдельная строка метаданных | Карточка / детальная страница | Недостаточно самостоятельной ответственности                  |
| Универсальная кнопка        | В родительских компонентах    | На этапе анализа достаточно общих стилей и нативной семантики |

## Этап 4. Состояния и интерактивность

### 4.1. Таблица интерактивных состояний

| Элемент         | Default          | Hover / Focus                     | Active / Selected                       | Loading / Disabled                | Error / Success / Empty             |
| --------------- | ---------------- | --------------------------------- | --------------------------------------- | --------------------------------- | ----------------------------------- |
| Основная кнопка | Доступна         | Контрастный hover, видимый focus  | Нажатие                                 | Spinner; disabled без мест        | Ошибка действия / подтверждение     |
| Фильтр          | Не выбран        | Подсветка и focus-ring            | Выбран, виден в активных                | Блокируется при обновлении        | Empty после комбинации фильтров     |
| Избранное       | Контурная иконка | Подсветка, focus                  | Заполненная иконка, `aria-pressed=true` | Временно disabled                 | Возврат состояния при ошибке        |
| Вкладка         | Неактивна        | Hover и клавиатурный focus        | Активная вкладка и панель               | —                                 | —                                   |
| Каталог         | Результаты       | Карточки реагируют на hover/focus | Активные фильтры                        | Skeleton / индикатор              | Ошибка загрузки / ничего не найдено |
| Форма           | Пустая           | Focus поля                        | Заполненные значения                    | Кнопка заблокирована при отправке | Ошибка поля / успешная заявка       |

### 4.2. Логика ключевых действий

| Действие пользователя           | Что происходит                                              | Во время ожидания                | При ошибке                                                            |
| ------------------------------- | ----------------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------- |
| Вводит запрос или меняет фильтр | Результаты пересчитываются, страница пагинации сбрасывается | Индикатор обновления             | Сообщение с возможностью повторить                                    |
| Добавляет событие в избранное   | Состояние меняется во всех местах показа события            | Кнопка временно блокируется      | Предыдущее состояние восстанавливается                                |
| Переключает вкладку             | Показывается связанная панель, обновляются ARIA-атрибуты    | Не требуется                     | Первая вкладка используется как безопасная по умолчанию               |
| Нажимает «Записаться»           | При наличии мест открывается форма регистрации              | Кнопка показывает loading        | Сообщение об ошибке и повтор действия                                 |
| Отправляет форму                | Проверяются обязательные поля и формат e-mail               | Повторная отправка заблокирована | Ошибка выводится рядом с полем и связывается через `aria-describedby` |
| Получает успешный ответ         | Показывается подтверждение и переход в «Мои события»        | —                                | —                                                                     |

### 4.3. Обязательные состояния, отсутствующие на основном макете

- пустой каталог после применения фильтров;
- загрузка каталога и отправки формы;
- отсутствие свободных мест и disabled-состояние записи;
- локальная ошибка некорректного e-mail;
- ошибка сети с возможностью повторить действие;
- успешная отправка формы;
- видимый клавиатурный focus для всех интерактивных элементов.

Эти состояния обязательны, потому что макет показывает отдельные снимки интерфейса, а реальный
сервис должен объяснять пользователю результат каждого действия и безопасно обрабатывать ошибки.
